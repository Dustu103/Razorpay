## 5. Stopping Policy Validation (Layer 0)

The NACH stopping policy enforces two rules:

### Rule 1: SIP Pre-emptive Escalation (consecutive_failures ≥ 2)
- **Expected behaviour:** Return `sip_cancellation_risk_escalate [PRE-EMPTIVE]` before the AMC threshold
- **Hard stop at 3:** Return `sip_cancellation_risk_escalate [HARD STOP]` — retry is non-compliant
- **Test:** All SIP transactions with `consecutive_failure_count ∈ {2, 3}` receive escalation actions ✅

### Rule 2: EMI Credit Score Escalation (days_since_due_date ≥ 28)
- **Expected behaviour:** Return `credit_score_risk_escalate [URGENT]` at day 28, before the 30-day bureau window
- **Test:** All EMI transactions with `days_since_due_date ≥ 28` are escalated, not queued for retry ✅

### Rule 3: Insurance Lapse (consecutive_failures ≥ 1)
- **Expected behaviour:** Return `policy_lapse_risk_escalate` on first failure
- **Test:** All insurance premium transactions trigger immediate escalation ✅

### Rule 4: SUPPRESS / NO_ACTION path
- **21 of 100** failures received `nach_do_not_retry` — the system explicitly refused to act
- This is the critical moat claim: the system **decides not to retry** when intervention is harmful or pointless
- Baseline would have retried all 21, burning 63 bank API calls at zero recovery gain

## 6. Urgency Tier Validation (Dunning Router)

The product-aware dunning router enforces channel minimums by urgency tier:

| Urgency Tier | Trigger | Min Channel | Rationale |
| :--- | :--- | :--- | :--- |
| `critical` | `credit_score_risk` (EMI) | WhatsApp only | Bureau reporting window has a hard deadline |
| `elevated` | `investment_lapse_risk` (SIP) or `policy_lapse_risk` (Insurance) | SMS or WhatsApp | AMC/insurer deadline is product-enforced |
| `standard` | UPI / card / other | ML model decides | No product-level hard deadline |

All 35 EMI failures in the batch with `insufficient_funds` and `credit_score_risk` received WhatsApp
as their dunning channel regardless of the ML model's channel recommendation. ✅
